# komek.kz

Сервис помощи с повседневными делами в Астане: бытовые задачи, перевозка вещей и поручения. Этот репозиторий содержит сайт для обращения в сервис.

## Что работает

- Заявка на сайте без регистрации и обязательного адреса квартиры.
- Кнопки WhatsApp и звонка. Номер не показывается текстом, но присутствует в ссылках связи.
- Выбор категории задачи, мобильное меню и ответы на частые вопросы.
- Тёмное оформление, локальный шрифт Inter, SVG-иконки и логотип komek.
- Исходное видео проекта: YouTube загружается после нажатия.

Личных кабинетов и отдельного приложения сейчас нет. Сайт написан на HTML, CSS и JavaScript без сборщика. Node.js и Playwright нужны только для автоматических проверок.

## Файлы

| Путь | Назначение |

| `index.html` | Главная страница и форма заявки |

| `tests/site.cjs` | Проверки формы, навигации и вёрстки |
| `tests/analytics.cjs` | Проверки счётчика с подменой Яндекс Метрики и сервера заявок |
| `RELEASE_CHECKLIST.md` | Нерешённые вопросы и ограничения проверки |

Форма обращается к существующему Cloudflare Worker. Его исходников в этом репозитории нет. Успешная проверка интерфейса не подтверждает фактическую доставку обращения оператору.

## Локальный запуск

Из корня репозитория, если установлен Python:

```sh
python -m http.server 8000 --bind 127.0.0.1
```

Открыть http://127.0.0.1:8000/. После редактирования файлов обновить страницу. При таком запуске форма использует реальный сервер; для проверки отправки без реальных заявок предусмотрены автоматические тесты ниже.

## Проверки

```sh
npm install
npx playwright install chromium
npm run check
npm test
```

Тесты перехватывают внешние запросы и не отправляют реальные заявки. Проверяются успешная отправка, ошибки, таймауты, сохранение текста, защита от повторного нажатия, мобильное меню и ширины экрана 320–1440 px. Отчёт и скриншоты сохраняются в `.qa/site/` и не коммитятся.

Необязательные переменные окружения:

- `KOMEK_BROWSER` — путь к установленному Chrome/Chromium.
- `KOMEK_PLAYWRIGHT` — путь к уже установленному модулю Playwright.
- `KOMEK_SKIP_VIDEO=1` — пропустить проверки неизменённого видео.

## Аналитика

Счётчик Яндекс Метрики `113258894` подключён на главной, странице условий и странице персональных данных. Он работает по HTTPS на `saimonsetish.github.io/pomoshik-kz/`, `komek.kz` и `www.komek.kz`. Локальные просмотры и другие домены не учитываются; при смене домена обновить список в `analytics.js`.

В Метрике нужно добавить три цели типа **«Целевое событие» / JavaScript-событие**, указав точное совпадение идентификатора:

| Идентификатор | Что означает |
| --- | --- |
| `whatsapp_click` | Нажатие ссылки WhatsApp, ещё не отправленное сообщение |
| `phone_click` | Нажатие ссылки звонка, ещё не состоявшийся разговор |
| `order_received` | Сервер формы ответил HTTP 2xx; доставка оператору и выполнение заказа этим не подтверждаются |

Цели добавляются в кабинете Метрики, а не автоматически этим кодом. [Инструкция Яндекса](https://yandex.ru/support/metrica/ru/general/goal-js-event).

Вебвизор, карта кликов, электронная коммерция и автоматический учёт внешних ссылок выключены. В события передаются только фиксированные имена, без телефона и содержимого заявки. Поля формы дополнительно исключены из записи классами Метрики. Не включать автоматический сбор контактных данных / Advanced Matching в кабинете. Сама Метрика получает обычные технические сведения о визите и использует cookies; это описано в `privacy.html`.

Для источников можно использовать ссылки с UTM-метками, например `?utm_source=threads&utm_medium=social&utm_campaign=launch`. Не помещать телефоны, имена или другие персональные данные в URL и UTM-метки.

Без JavaScript или при блокировке Метрики посещения не попадут в счётчик. Отдельный `noscript`-пиксель не добавлен, чтобы локальные просмотры без JavaScript также не отправляли данные. Работа формы и контактов от загрузки счётчика не зависит.

## Публикация

GitHub Pages публикует ветку `main`. После отправки изменений проверить выполнение **pages build and deployment** во вкладке Actions. Изменения в другой ветке сами по себе действующий сайт не обновляют.

Перед работой получить актуальные изменения и проверить `git status`. Вносить только относящиеся к задаче правки, выполнить подходящие проверки и согласовать публикацию в рамках задачи. Не добавлять в репозиторий пароли, токены, персональные данные клиентов или внутренние рабочие документы.
